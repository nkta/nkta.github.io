## 1. ☕ JDK : JDK 27 et 28 en approche, Valhalla se concrétise

### JDK 27 — Rampdown phase en cours

La version 27 (prévue pour septembre 2026) entre dans sa phase de rampdown : les JEPs sont figées, place aux corrections de bugs.

**Nouveauté notable :** G1 devient le garbage collector par défaut dans **tous les environnements**. Fini la distinction entre client et serveur — G1 est désormais le choix unique par défaut.

Sources : [OpenJDK Quality Outreach](https://inside.java) (Juillet 2026)

### JDK 28 — En développement actif

- Nouveau plugin **`jlink cacerts`** pour embarquer les certificats racine au moment du build
- Améliorations de sécurité pour les images runtime personnalisées

### JDK 26 — Retrospective

Un article détaillé sur les améliorations de performance de JDK 26 a été publié : SIMD Vector API progresse avec l'auto-vectorization dans HotSpot.

### Project Valhalla — Ça devient concret

Deux articles majeurs sur inside.java :
- **« Identifying JDK Value Class Candidates »** — identification des classes du JDK qui passeront en *value types* (sans identité, allouées inline)
- **« Better Tools for Immutable Data »** — nouveaux outils pour manipuler les données immuables

Les `value class` et `primitive class` approchent. L'impact sur la performance mémoire sera considérable (tableaux d'objets contigus, pas d'overhead d'en-tête).

### Project Babylon — Java sur GPU

- **Under the HAT** : Accélération GPU pour Java via le Panama HAT (HotSpot Ability Tool)
- **Tensor Cores** : Exploitation des cœurs tensoriels NVIDIA directement depuis Java

### ZGC : 10 ans

Article rétrospectif : *ZGC: A Decade of Redefining Java Performance* — retour sur une décennie de GC à faible latence.

### JIT Compiler

Épisode 64 du podcast Inside Java : *« JIT Compiler From the Ground Up »* — pour comprendre comment HotSpot compile et optimise le bytecode.

**Articles chauds du mois :**

#### 🔥 To Cache or Not to Cache Virtual Threads (28 juillet)
L'équipe Quarkus (Francesco Nigro) a testé ce qui se passe quand on « pool » les virtual threads — alors que l'OpenJDK recommande de ne pas le faire. Résultat : le pooling casse les performances et la JVM ne peut pas corriger ce comportement. **Conclusion : ne jamais pooler les virtual threads**, faites-leur confiance.

#### 🔥 Improving a Competitor's Numbers (On Purpose) (21 juillet)
Francisco Nigro explique comment Quarkus a découvert que son benchmark sous-mesurait Spring à cause d'un warmup insuffisant. Au lieu de laisser l'avantage, ils ont corrigé le benchmark pour mesurer Spring à son pic de performance. Résultat : les scores Spring ont augmenté, Quarkus est resté identique. Une leçon de transparence.

#### Quarkus Shim (17 juillet)
Nouvelle extension pour patcher des classes Java **au moment du build**. Compatible JVM mode, dev mode et native executable. Une alternative propre au bytecode instrumentation au runtime.

#### Quarkus Insights #254 — DDD et Architecture Hexagonale (14 juillet)
Deuxième partie avec implémentation concrète : commandes, aggregates, value objects, outbox pattern, ArchUnit.

## 3. 📚 Outils, bibliothèques et pratiques

### Spring AI 2.0 — La grosse sortie du mois

La version 2.0 apporte une fonctionnalité clé : **le structured output auto-correctif**.

```java
// Spring AI 2.0 — Structured Output auto-correctif
@RestController
class AiController {
    private final ChatClient chatClient;
    
    @GetMapping("/recommend")
    MovieRecommendation recommend(@RequestParam String genre) {
        return chatClient.prompt()
            .user("Recommend a " + genre + " movie")
            .call()
            .entity(MovieRecommendation.class);
        // Si le JSON retourné ne correspond pas au schéma,
        // Spring AI corrige automatiquement et réessaye
    }
}
```

Le LLM génère du JSON, Spring AI valide contre un schéma (Pydantic-style), et si la validation échoue, il auto-corrige la réponse. Plus d'excuses pour du JSON mal formé.

### Java + MCP (Model Context Protocol)

Article sur inside.java : *« Pairing In-Process and Hosted Embeddings for Java MCP Tool Development »*. Le MCP s'intègre nativement avec Spring AI 2.0 — les outils Java peuvent être exposés comme des outils MCP pour les LLMs.

### Java vs Go : Benchmark 2026

*« Can Java Microservices Be As Fast As Go? A 2026 Benchmark Update »* — avec Project Leyden et GraalVM native, Java rattrape Go sur le démarrage à froid. Les microservices Java natifs deviennent une option crédible pour les architectures serverless.

### Agentic Coding pour la migration

Article Oracle : *« How Agentic Coding Can Help You Migrate Java Applications Faster »* — les coding agents (Claude Code, etc.) appliqués à la migration de vieilles bases Java.

## 5. 🔮 Analyse et perspectives

### ✅ Impactant — À adopter rapidement

1. **Spring AI 2.0** : si vous faites de l'IA en Java, c'est maintenant. Le structured output auto-correctif résout un vrai problème.
2. **Virtual Threads : ne pas les pooler** — validé par l'expérimentation Quarkus. Architecture à revoir si vous utilisiez des pools de threads pour l'I/O.
3. **Valhalla se concrétise** — les value types arrivent. Préparez vos modèles de données.

### ⚪ Anecdotique — Pas d'urgence

- JDK 28 `jlink cacerts` : utile mais très spécifique
- Quarkus 3.38 weight-based eviction : amélioration incrémentale du cache Hibernate
- Spring Boot 3.5.16 : simple maintenance

### 👀 À surveiller

- **Spring Boot 4.x** : pas encore GA mais les articles s'accumulent. La migration depuis 3.x demandera de l'attention (Virtual Threads par défaut, Jakarta EE 11)
- **Project Leyden + GraalVM** : si Java natif devient aussi rapide que Go au démarrage, ça change la donne pour le cloud et le serverless
- **Project Babylon** : Java sur GPU est encore expérimental mais prometteur pour le calcul intensif
