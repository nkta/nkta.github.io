# Veille MCP — Août 2026

*Auteur : Nicolas Koudota — 1er septembre 2026*

*Période couverte : août 2026 (1 → 31)*

> Le mois où MCP est devenu **stateless** en production. La spécification 2026-07-28, passée en stable le 28 juillet, a fait d'août le grand chantier de migration et d'adoption — et il a coïncidé avec la plus grosse vague de vulnérabilités jamais observée sur le protocole.

---

## 🔥 Les 3 faits marquants

- **Le passage au *stateless* est (presque) réussi** 🚀 : la 2026-07-28 supprime le handshake `initialize` (SEP-2575) et les sessions `Mcp-Session-Id` (SEP-2567). Un mois après, la migration se fait sans cutover planifié pour la plupart des équipes — les SDK Tier 1 (TypeScript, Python, Go, C#) ont tous livré un stable le jour de la release, et **Cloudflare a poussé son support la veille du date-stamp**. La leçon : un changement cassant bien outillé (compat des deux côtés, SDKs prêts, `server/discover` optionnel) peut être absorbé sans migrer « en une nuit ».
- **Le déluge de CVEs MCP** 🔒 : jamais autant de failles publication. Le 27 août, VulnCheck a publié **12 CVEs en une seule minute** sur les transports HTTP MCP (DNS rebinding, listeners non authentifiés, SSRF, sandbox escapes). Sur tout le mois : **SiYuan ×4**, Spring AI, Java SDK, PHP SDK, n8n, Splunk (RCE 9.1), Grafana SSRF (9.1), mcp-memory-service (9.8 et 9.1), UFO Microsoft (9.4), Onyx (9.6)… Les scans indépendants estiment que **30 à 82 % des serveurs publics exposent au moins un défaut exploitable**.
- **MCP se standardise en profondeur** 🏛️ : nouvelle **roadmap** (22 août, 5 priorités), **3 groupes de travail** chartés en août (Transports le 26, Apps le 12, Agents le 5), **Rust SDK promu Tier 1** (21 août), dépôts de normes qui se multiplient (Agent Plugins 1.0, ID-JAG, MCPA). Le registre dépasse **9 650 serveurs** officiels ; l'agrégat cross-registries atteint ~**15 930**.

## 1. Spécification & versions — MCP devient *stateless*

Aucune nouvelle révision n'a été publiée en août : la **2026-07-28** reste la référence stable, et son déploiement a monopolisé le mois.

**Ce qui change structurellement** (le plus gros changement depuis le lancement) :

- Le handshake `initialize`/`initialized` est **supprimé** (SEP-2575) : les capacités et infos client voyagent désormais **dans un champ `_meta` sur chaque requête**, via `io.modelcontextprotocol/protocolVersion`, `clientCapabilities` et `clientInfo`.
- L'en-tête `Mcp-Session-Id` (et donc la notion de session) est **retiré** (SEP-2567) : n'importe quelle requête peut atterrir sur n'importe quelle instance → **plus besoin de sticky sessions ni de Redis/passthrough de session** pour scaler.
- **Multi Round-Trip Requests** (SEP-2322) remplacent les requêtes initiées par le serveur, avec un `requestState` opaques signé par HMAC.
- **Extensions** formalisées (SEP-2133) ; le framework `io.modelcontextprotocol/tasks` est extrait du cœur.
- Un **header-based routing** (`Mcp-Protocol-Version`, `Mcp-Method`, `Mcp-Name`) permet l'aiguillage et le cache au niveau du load balancer.
- **Politique de cycle de vie** adoptée : 3 états, fenêtre de dépréciation **minimum 12 mois**, page de registre des dépréciations, SDKs Tier 1 obligés de les exposer en langage.

**Dépréciations à connaître** (SEP-2577) : `Roots`, `Sampling`, `Logging` restent dans la spec 12 mois, mais les nouvelles implémentations ne doivent plus les utiliser. `Roots` → passer le contexte filesystem par paramètres d'outil ; `Sampling` → appeler directement l'API du fournisseur.

**Code d'erreur** : la valeur d'erreur des paramètres invalides passe de `-32002` à `-32602` (facile à rater).

> ✅ **Piste d'action** : toute nouvelle brique MCP doit viser la 2026-07-28 dès le départ. Pour l'existant, la fenêtre de migration sûre va jusqu'à la prochaine grande révision (cible **2026-12-15**).

## 2. Implémentations — SDKs & serveurs de référence

### SDKs officiels (Tier 1 = TypeScript, Python, C#, Go, + **Rust** depuis le 21/08)

Les **renommages** sont le piège n°1 de la migration :

- **Python v2** : `FastMCP` est renommé **`MCPServer`** et le module `mcp.server.fastmcp` a été **supprimé** (pas simplement déprécié) — un `pip install mcp` non épinglé vous donne aujourd'hui `MCPServer`. Les options de transport sont déplacées du constructeur vers `run()`. Le package a repris le nom `mcp` sur PyPI.
- **TypeScript v2** : l'ancien monolithe `@modelcontextprotocol/sdk` est splitté en **9 paquets scoped** ; désormais **ESM-only** ; `.tool()` devient `registerTool`.

```python
# v1 — impossible si votre import résout : vous êtes encore en 1.x
from mcp.server.fastmcp import FastMCP
app = FastMCP("orders", stateless_http=True)   # transport sur le constructeur
app.run()

# v2 — pip install "mcp[cli]>=2.0.0"
from mcp.server import MCPServer
mcp = MCPServer("orders")                      # transport sur run()
@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b
mcp.run()                                      # transport passé ici
```

```bash
# TS v2 — paquets scoped + codemod de migration
npm install @modelcontextprotocol/server@beta
npm install @modelcontextprotocol/client@beta
npx @modelcontextprotocol/codemod@beta v1-to-v2 .
```

## 3. Intégrations tierces & adoption éditeurs

Le mois a été riche en annonces d'adoption de la part des grandes plateformes :

- **Microsoft Foundry** : les **5 capabilities Claude** — dont le **MCP Connector** (pointer les `Messages` API vers des serveurs MCP distants, sans client ni traduction de schéma) — sont désormais dispo sur les déploiements **Hosted on Azure** (12 août), pas seulement sur Hosted on Anthropic. Résout le dilemme résidence de données vs capacités agentiques. (Beta.)
- **Azure DevOps Remote MCP Server** : passage en **GA** (mi-août, InfoQ). Mais **Claude Desktop/Code, ChatGPT et Cursor ne s'y connectent pas** : auth via Microsoft Entra, et les clients tiers exigent l'*OAuth dynamic client registration* ou *Client ID Metadata Documents* — mécanismes qu'Entra ne supporte pas encore (et dont l'un est déjà déprécié dans la 2026-07-28 !). Illustration que **la couche d'identité reste propriétaire**, même quand le protocole est standard.
- **GitHub Copilot** : **allowlists MCP centralisées** (allow/deny `McpServers` en enterprise settings, fail-closed) le 6 août ; **Agent Plugins 1.0** en **GA** dans VS Code, Copilot CLI, SDK et app (12 août) — le format de paquet vendor-neutral qui bundle skills + `mcp.json` ; **MCP Connectors canvas** (20 août) pour brancher un serveur hébergé via Azure Connector Namespace **sans URL ni header ni proxy local**.
- **Codex CLI (OpenAI)** : 0.147.0 — support **opt-in** de la 2026-07-28 (discovery paginé, multi-round, démarrage non-bloquant) + installation d'Agent Plugins (7 août).
- **Cloudflare** : Agents SDK **v0.20.0** (27 juil.) ; **Gateway détecte le trafic MCP** (politique `Is MCP` + dashboard AI Security, 12 août) — première visibilité réseau native sur le protocole.
- **AWS** : Bedrock AgentCore **Gateway** signale les versions qu'il parle (+ support opt-in 2026-07-28, `UpdateGateway`) ; **DocumentDB MCP** (read-only bypass corrigé).
- **Vercel / Netlify / Notion** : `mcp.vercel.com` sert la 2026-07-28 (31 juil.) ; `mcp-handler 2.0` répond `/sse` en 410 ; Netlify (28 juil.) ; **Notion** premier vendor adoptant hors cluster release-day (3 août).
- **Anthropic** : **Enterprise-Managed Auth GA** pour connecteurs MCP (24 août) — admins Claude Team/Enterprise provisionnent via IdP ; ajout de Datadog, Notion, Slack (Exa, Miro, Zoom « coming soon ») ; Okta seul IdP à la sortie.

> 👀 **Ce qui ressort** : l'édition Enterprise (auth managée, allowlists, canvas sans credentials) progresse plus vite que l'édition grand public. La gouvernance d'accès devient le vrai champ de bataille — et il reste morcelé (Entra vs ID-JAG vs scopes par appel).

## 4. Migration & retours d'expérience

### Le constat : c'est parti plus vite que prévu

Les analyses de fin août (« A Month On, the Stateless MCP Transport Migration Is Mostly Done ») convergent. Détails clés de la stratégie de compatibilité qui a fonctionné :

- **Day-zero tooling** : Cloudflare a livré le support du SDK **la veille** du date-stamp de la spec.
- **Fallback intelligent** : les Cloudflare MCP portals (25 août) acceptent les requêtes 2026-07-28 **et** les clients Streamable HTTP 2025 ; en connectant l'upstream, ils **testent** le support et retombent sur le handshake 2025 si besoin.
- **Compromis ponctuel** : le manque d'embedded client dans le SDK v2 a été comblé par un `server/discover` **optionnel** — un client qui veut inspecter le serveur peut l'appeler, mais ce n'est plus obligatoire.

### Le vécu terrain (ce qui casse)

- **Renommages cassants** : `FastMCP`→`MCPServer` (la suppression de `mcp.server.fastmcp` a cassé du code le jour même — AWS a épinglé sa collection de serveurs sous 2.0.0), scission TS en 9 paquets, ESM-only.
- **Context** : le `request_context` global (ContextVar) est **supprimé** au profit d'une injection propre `ctx: Context` ; `ctx.fastmcp` → `ctx.mcp_server`. Le contexte devient **request-scoped**, plus session-scoped.
- **Listes → cacheables** : `tools/list`, `resources/list`, `prompts/list` ne doivent plus dépendre d'un état ou d'un appel antérieur, sinon le load balancer ne peut pas les mettre en cache.
- **Long work / SSE** : le streaming et les connexions longues partent vers l'**extension Tasks** (SEP-2663).

### Exemple : requête stateless (modèle d'en-têtes)

Obtenu via AWS AgentCore Gateway et Google Developers Blog — une requête autoportante, sans session préalable :

```http
POST /mcp HTTP/1.1
Host: mcp-server.example
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: search
Content-Type: application/json

{ "jsonrpc": "2.0", "id": 1, "method": "tools/call",
  "params": { "name": "search", "arguments": { "q": "otters" },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {},
      "io.modelcontextprotocol/clientInfo": { "name": "my-app", "version": "1.0" } } } }
```

L'inspection optionnelle (remplace `initialize`) :

```http
POST /mcp HTTP/1.1
MCP-Protocol-Version: 2026-07-28
Mcp-Method: server/discover

{ "jsonrpc": "2.0", "id": 1, "method": "server/discover" }
```

### Les classes de failles qui reviennent (pattern 2026)

1. **Validation d'en-tête Host absente/désactivable** → **DNS rebinding** (mcp-go, Dropbox Dash, Timescale ×3).
2. **Listeners exposés sans authentification** (Telnyx 9.1, UI-TARS 10.0, mcp-router) — surtout sur les transports mobiles/desktop.
3. **SSRF et redirect de token** : l'URL de destination contrôlée depuis un argument de modèle ou un header `X-*`, souvent avec le **PAT en bearer** (Grafana, Contentful, Apify, CKAN, SkyWalking, DocumentDB).
4. **Épuisement de ressources / buffers illimités** (Java SDK, Spring AI, PHP SDK SSE) — pas de `Content-Length` cap.
5. **Bypass de politique** : `approval_requirement: Auto` (CodeWhale), read-only bypassé par `$out/$merge` (DocumentDB), politique qui échoue **silencieusement** (AWS API MCP).
6. **Outils `roots` / symlinks** contournés (Chrome DevTools MCP) — comparaison de chemins sans résolution de liens symboliques.

### Gouvernance : MCP mûrit en vitesse

- **Nouvelle roadmap** (22 août) : 5 priorités — primitives de messagerie agentique, unification des transports HTTP, **identité agent & sécurité entreprise**, primitives améliorées, **expérience développeur SDK**.
- **Transports Working Group** charté (26 août), piloté par Kurtis Van Gent : bindings de transport, scalabilité, migration hors des modèles session ; roadmap contre la **release 2026-12-15**.
- **Apps WG** (12 août, spec `ui` SEP-1865) et **Agents WG** (5 août, stabilisation de l'extension `tasks` dans le cœur, mené par AWS + Microsoft).
- **Rust SDK promu Tier 1** (21 août) — 67/67 checks serveur, 50/50 client de la suite de conformité.
- **Registre** : v1.8.1 (6 août) bloque les domaines `github.io` **après une prise de contrôle potentielle de namespace d'organisation** — corrigé en ~65 minutes, sans CVE.
- **Certification MCPA** (Association Agentic AI / Linux Foundation) : la première certif officielle.
- **Nick Aldridge** passe co-mainteneur émérite (5 août) ; mouvement de vie du projet, pas de départ à vide.

> ⚠️ **À retenir** : le point dur du mois n'est plus « comment brancher un agent » mais **« comment sécuriser le transport et les credentials »**. Les stats de scans indépendants (30 → 82 % de serveurs publics avec défaut exploitable) et le lot de 12 CVEs du 27 août sont un signal fort : si vous exposez un serveur MCP, **la revue de surface d'attaque est prioritaire**.

## Analyse critique

- ✅ **Impactant — à agir**
  - **Migrer vers la 2026-07-28** : les SDKs Tier 1 sont prêts, `server/discover` est optionnel, la compat est conçue (pas bricolée). Un serveur simple (file, API wrapper) = mise à jour SDK + headers, à tester contre la RC.
  - **Sécuriser le transport MCP** : Host-header validation, auth sur tous les listeners, bind loopback pour les serveurs locaux, limites de body, blanchiment des URL contrôlées par le modèle. C'est le nouveau front de l'agent-sécurité.
  - **Épingler les dépréciations** : `Roots`/`Sampling`/`Logging` ont 12 mois, mais le long work part vers la Tasks extension — planifiez.
  - **Scopes par appel d'outil** (github-mcp-server 1.11.0) : le bon réflexe de moindre privilège, à imiter dans vos propres serveurs.
- ⚪ **Anecdotique — pas d'urgence**
  - Renommages SDK (FastMCP→MCPServer, split TS) : marketing-undo churn, mais douloureux pour qui était sur 1.x.
  - Le lot de 12 CVEs du 27 août : beaucoup concernent des serveurs de niche (Timescale, mcp-router, ToolUniverse) — à trier selon votre surface réelle.
  - Nombre d'« annonces » d'adoption (Vercel, Netlify, Notion) : des sondes `server/discover`, pas de rupture fonctionnelle.
- 👀 **À surveiller**
  - **Couche d'identité** : Entra vs ID-JAG vs enterprise-managed auth — la standardisation de l'auth reste le chantier non résolu (l'exemple Azure DevOps Remote MCP le montre).
  - **Prochaine révision 2026-12-15** : le Transports WG a déjà son planning ; la fenêtre de migration se resserre.
  - **Certification MCPA** : va devenir un critère de sélection dans les boîtes ? (elle classe le standard « métier »).
  - **Sécurité supply-chain** : l'incident du maintainer blender-mcp (compte GitHub hijacké le 11 août) rappelle que la confiance porte aussi sur les dépôts, pas seulement sur le protocole.

## Conseils / enseignements pratiques

1. **Votre serveur MCP doit être stateless par design** : pas d'état par « session », listes cacheables, `_meta` par requête. Si vous avez une vraie session (panier, contexte long), **mintéz un handle explicite** renvoyé par l'outil — c'est le pattern documenté.
2. **Déployez en serverless sans scrupule** : plus de sticky sessions Ni de session store → Lambda, Cloud Run, Cloudflare Workers, Azure Container Apps derrière un round-robin. AWS a rendu l'opt-in une seule appel `UpdateGateway`.
3. **Sécurisez l'accès comme une API publique** : validation d'origine, auth OAuth Ressource-Server, `allowlist` plutôt que denylist (les noms d'outils inconnus warnent plutôt qu'erreur — vérifiez en CI), scopes par appel.
4. **Testez la compatité en CI** : avec la 2026-07-28, un client ne *doit* plus faire de handshake — mais un vieux serveur en a encore besoin. Les SDKs (mode hybride C#, portals Cloudflare) servent les deux ; tester les deux chemins.
5. **Ne vous fiez pas aux blogs pour la graduation des features** : la suite de conformité et le registre des dépréciations (page officielle) font foi.

## Mise en perspective

- **Un protocole, pas une API.** Le passage stateless renforce la lecture « MCP = standard d'interop », qui rapproche du *Language Server Protocol* : un format commun, une couche d'identité et de gouvernance à part. On n'écrit plus « un client MCP » : on consomme des serveurs publiés dans un registre.
- **L'interopérabilité progresse plus vite que la sécurité.** Les ~15 930 serveurs publics, la certification MCPA, les 3 groupes de travail et l'adoption des éditeurs (Microsoft, AWS, Google, Cloudflare, GitHub, Vercel) montrent une standardisation très rapide. Mais la vague de CVEs indique que **la sécurité suit un train de retard**, et que la couche d'identité reste propriétaire.
- **Impact sur les devs / agents** : le *stateless* rend les intégrations à la fois plus simples à déployer (serverless) et plus dures à fiabiliser (pas de conversation de session). Pour l'industrie, ça rabote le coût d'infra des intégrations MCP et ça ouvre la porte à des gateways d'entreprise (Bedrock AgentCore, Foundry Connector) qui gouvernent les credentials centralement — un vrai signal de maturité *et* de verrouillage plateforme.
